urweb-curl: HTTP requests from Ur/Web
=====================================

An Ur/Web library that makes an HTTP request from io code, over libcurl, and
says what became of it.  `curl.urs` is the interface: `Curl.perform` takes
the options (headers, body, authentication, TLS, timeouts, size limit,
redirects), a method and a URL, and returns the outcome: the answer, with
its status, headers and body, or why there is none.  A request is not
something a transaction can undo, so there is no making one from a
transaction: an io task, or a function called with `io_rpc`, claims what is
to be sent in one transaction, sends, and records the outcome in another.
Needs an Ur/Web with the `io` monad.

    fun createPayment (key : string) (order : orderId) : io (result url) =
        r <- Curl.perform (Curl.Opts.default -- #Auth -- #Body -- #Headers
                           ++ { Auth = Curl.Bearer key,
                                Body = Some (Curl.form (("amount", "12.00") :: [])),
                                Headers = ("Idempotency-Key", show order) :: [] })
                          Curl.Post (bless "https://api.example.com/v2/payments");
        return (case r of
                    Curl.Answered a =>
                    if a.Status = 201 then parse a.Body
                    else Failure <xml>the provider said {[a.Status]}</xml>
                  | o => Failure <xml>{[show o]}</xml>)

What the outcome says
---------------------

- `Answered r`: the server answered, with any status; the caller judges.
  `r.Headers` are the final response's, as sent; `r.Body` is decoded if the
  server compressed it.  With `FollowRedirects` at 0, the default, a 3xx is
  the answer; with more, the last response is, and when more redirects were
  needed than allowed, the last 3xx.
- `BadOpts m`: the options are not usable (a header name that is not a
  token, a value with a line break, a Content-Type header beside a body, a
  body on a HEAD, a timeout or limit that is not positive, ...); nothing was
  sent.
- `NotSent m`: nothing of the request reached the server -- the name did not
  resolve, the connection or the TLS handshake failed, it timed out before
  sending.  Sending again is safe.
- `MaybeSent m`: the request went out and no complete answer came back -- the
  connection was lost, or the transfer timed out.  The server may have acted
  on it; sending again may act twice.  For a request that must not, an
  idempotency key the server honours (as in the example) makes the retry
  safe.
- `ResponseTooLarge n`: the server answered with more than `MaxResponse`
  (headers and body); it has acted, and the answer was given up.

Nothing on the way throws for a condition of the network or the server; in
io nothing could be caught.

What is sent
------------

- The method as given, the body with its `ContentType`; `Curl.form` encodes
  fields as `application/x-www-form-urlencoded` (percent-encoding the bytes
  of UTF-8, as libcurl does), `Curl.json` labels JSON text.  A POST without a
  body sends `Content-Length: 0`.
- The headers given, in order; `User-Agent: urweb-curl/VERSION` unless one
  is given; no `Expect: 100-continue`, unless given.  `Bearer` is an
  `Authorization` header, `Basic` libcurl's own.
- Only `http` and `https` are spoken, redirects included.  The URL is one
  the application's `allow url` rules admit: the policy is the
  application's, and the library adds none.  libcurl reads the usual proxy
  variables (`https_proxy`, `no_proxy`).
- An https server's certificate is verified against the system's CAs, or
  `Verify (Some caFile)`; `NoVerify` is for a development server with a
  self-signed certificate, never for production.

A connection the server keeps open is kept by the task for its next
request.  `URWEB_CURL_DEBUG=1` traces every request on stderr, libcurl's own
trace less the value of the Authorization header.

Building
--------

    ./autogen.sh
    ./configure --with-urweb=PREFIX   # where urweb is installed; defaults to
                                      # the prefix of the urweb on the PATH
    make
    make check                        # the tests, see below
    make install

`configure` finds libcurl (7.55.0 or later) through pkg-config.  Everything
an application needs is installed under the prefix: the static library in
`lib/`, `curl.h` in `include/urweb/`, and in `lib/urweb/ur/urweb-curl/` the
signatures and the `.urp` files, so that an application imports the library
with

    library PREFIX/lib/urweb/ur/urweb-curl

`config.urp` there is generated by `configure` and names the header and the
libraries by absolute path, so no `-L` or `-I` flags are needed when the
application is compiled.

With Nix: `nix-build` builds and tests the library against the Ur/Web named
in `urweb-src.nix`; `nix-shell` gives a shell with what the build needs.  A
project that packages the library calls `derivation.nix` with its own
`urweb`.  Nix is not needed to build or use the library.

Tests
-----

    tests/run.sh [-u] [CASE...]

An Ur/Web application under `tests/app` makes every request once from an io
task, against a fake HTTP server (`tests/httpd.py`, python, standard
library only; one port plain, one with a self-signed certificate from
openssl), and logs what `Curl.perform` made of it; the log is split into one
transcript per case and compared with `tests/cases/CASE/expected`.  The
cases are in `tests/app/test.ur`.  `-u` rewrites the expected files.
`URWEB` names the compiler to use (with the flags in `URWEB_FLAGS`),
otherwise the one on the PATH; for an in-tree Ur/Web build, set
`LD_LIBRARY_PATH` to its `out/lib`.  The messages libcurl gives for a
failure are recorded with their numbers replaced by N; their wording is
libcurl's, so a different libcurl may word a failure differently.
